## Workload and statistical constants

The normal runner performs its precision work within each isolated
original-library worker. There is one canonical full run, not a later
replacement of selected rows. Start with at least 100 iterations and 2000 ms
measured work after 20 iterations and 1000 ms warmup. Continue in 2000 ms
batches until the combined RME is at most 4%, 24000 ms measured work has
accumulated, or worker wall reaches 480000 ms. Keep every measured sample,
including GC and outliers. JSON records each batch and whether the limit was
reached. The 5% display threshold remains unchanged. These are experimental
choices in `catalog.mjs` and `worker.mjs`. Repeated precision checks make the
nominal 95% interval descriptive, not a sequentially valid confidence guarantee.
Timing samples share JIT/GC state.

Lossless raw samples go to ignored `.cache/samples/<run token>/` and are linked
from each summary row. `results/` contains only latest.json, latest.md and
remote-guidance.md. Quick output defaults to `.cache/quick.*`; explicit
alternate outputs should also use `.cache/`. Generated result JSON is excluded
from treefmt; source files and Markdown remain formatted.

Graft retains up to 1000 replayed log entries by default
(`packages/core/src/Graft.ts:152`). The benchmark does not override that runtime
setting; empty-root subtraction excludes its root cost from per-plugin heap
estimates.

These are benchmark design choices, not production defaults. Their executable
source is `packages/benchmarks/catalog.mjs:17` and `:48`, with expected
observable work in `packages/benchmarks/src/expectation.ts`.

## Profiling and review corrections

`profile.mjs` uses the
[Node Inspector CPU profiler](https://nodejs.org/api/inspector.html#cpu-profiler).
Its 100 microsecond requested sampling interval, 5 discarded fixtures and 10
profiled operations are experimental inputs. Only fixture.run is profiled;
imports, root construction, observer assertions and disposal are excluded.
Profiles perturb execution, so profile wall times are not benchmark estimates.
Raw cpuprofile files stay in `.cache/profiles/`. Self samples and inclusive
stacks must be distinguished: inclusive categories overlap and cannot be summed.

Source paths for event ownership: `packages/core/src/Event.ts:110` creates the
registration scope/FiberSet once; `:139` restores registration context and runs
`Release.scoped` on every invocation; `:199` looks up/filter handlers; `:237`
claims each handler transactionally, starts a child with FiberSet.run and waits
for its full exit. `packages/core/src/Release.ts:78` creates/closes invocation
scopes and preserves both body and release causes.
`node_modules/effect/src/FiberSet.ts:718` uses forkUnsafe. Synchronous cordis
emit directly applies callbacks through its event service
(`node_modules/cordis/lib/index.js`, EventsService.emit). They do not provide
equivalent cancellation/resource guarantees. No core source changes.

The previous Remote run used the short 300 ms baseline budgets, discarding the
2–8 second sampling improvements of the earlier refined dataset. Archived
comparison in ignored cache: 10/154 original timing rows were noisy in the
refined dataset versus 126/154 in the fresh Remote run; four additional noisy
original memory rows explain the formerly quoted 130. The two short-budget
pre-Remote datasets had 120/151 and 123/154 noisy timing rows, respectively.
This is direct evidence of a budget/provenance regression. It does not establish
concurrent CPU load as the cause. Final runs do not overlap benchmark, build,
profile or test jobs. No root test worker cap is imposed. Root test-pool
failures and session incidents belong in the final response, not package
documentation.

The public Fork current-state API is a stream, not a synchronous property.
`packages/core/src/Graft.ts:281–305` builds both state and await; await itself
opens a settled-state stream subscription. The corrected adapter removes stable
and performs await followed by exactly one current-state read. An await-only
control remains a separately labeled diagnostic, rather than silently removing
the Active assertion. A no-barrier control failed its work oracle at 989/1000
activations; it is not a completed-load measurement.

The controlled before/after comparison uses copies of the compiled adapter that
differ only in `yield* fork.stable`. Each variant/scenario runs in a fresh Node
process with at least 20 warmups and 1000 ms measured warmup, then 9 samples;
variant order alternates across cases. These are experimental inputs, not
library defaults. All plugin counts and finalizers are checked. Memory
comparison timings are separately labeled load/cycle diagnostics; the canonical
heap results come from the full memory scenarios. Small median differences do
not prove causality.

Raw CPU profiles also contain Inspector.start/stop administrative samples even
though the logical operation timer excludes those commands. Report that weight
separately and normalize workload shares after excluding stacks containing
node:inspector; no workload outliers are removed and raw profiles are retained.
The weighting uses each sample's timeDeltas from the
[Profiler Profile format](https://chromedevtools.github.io/devtools-protocol/tot/Profiler/#type-Profile).
Inclusive FiberSet.run and Release.scoped percentages overlap and are not
additive. Context restoration executes via interpreter primitives, so its full
incremental cost is not separately identified by JavaScript stack sampling.
