the pinned installation and this worktree. Read the result report for
scenario-specific interpretations and evidence that could change them.

## Workload and statistical constants

The normal runner performs its precision work within each isolated
original-library worker. There is one canonical full run, not a later
replacement of selected rows. Start with at least 100 iterations and 2000 ms
measured work after 20 iterations and 1000 ms warmup. Continue in 2000 ms
batches until the combined RME is at most 4%, 24000 ms measured work has
accumulated, or worker wall reaches 480000 ms. Keep every measured sample,
including GC and outliers. JSON records each batch and whether the limit was
reached. The 5% display threshold remains unchanged. These are experimental
choices in `catalog.mjs` and `worker.mjs`. Repeated precision checks make the
nominal 95% interval descriptive, not a sequentially valid confidence guarantee.
Timing samples share JIT/GC state.

Lossless raw samples go to ignored `.cache/samples/<run token>/` and are linked
from each summary row. `results/` contains only latest.json, latest.md and Quick
output defaults to `.cache/quick.*`; explicit alternate outputs should also use
`.cache/`. Generated result JSON is excluded from treefmt; source files and
Markdown remain formatted.

Graft retains up to 1000 replayed log entries by default
(`packages/core/src/Graft.ts:152`). The benchmark does not override that runtime
setting; empty-root subtraction excludes its root cost from per-plugin heap
estimates.

These are benchmark design choices, not production defaults. Their executable
source is `packages/benchmarks/catalog.mjs:17` and `:48`, with expected
observable work in `packages/benchmarks/src/expectation.ts`.
