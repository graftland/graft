Graft 把應用程式當作一棵**外掛樹**來執行。本頁為各個部分命名，每一列都連結到詳細說明的頁面。

## 核心詞

這些詞在所有套件和頁面中只有一個含義。

| 詞                   | 說明                                                  | 延伸閱讀                                 |
| -------------------- | ----------------------------------------------------- | ---------------------------------------- |
| **Plugin**           | 宣告並實作一項能力的值：設定、相依、服務與啟動邏輯。  | [外掛](../plugins/)                      |
| **Instance**         | 部署中有穩定身分的外掛。Loader 項目的 id 就是實例名。 | [設定檔](../config-file/)                |
| **Service**          | Effect 的服務。Graft 補充執行期間的發布、撤回與租約。 | [服務](../services/)                     |
| **Contract**         | Effect 的 `RpcGroup` 加上每個操作的身分。             | [遠端契約](../remote/contracts/)         |
| **Realm**            | 服務與貢獻的可見邊界。                                | [領域](../isolation/)                    |
| **Deployment group** | 共用一個單元、單元結束時一同受影響的一組實例。        | [單元](../units/)                        |
| **Unit**             | 承載實例的 Worker、子行程或 runner 上的執行。         | [單元](../units/)                        |
| **Generation**       | 一個實例的一次執行，從啟動到結束。                    | [變更](../transitions/)                  |
| **Placement**        | 單元的種類及其管理者。                                | [單元](../units/)                        |
| **Artifact**         | 內容定址、執行期間位元組不變的外掛程式碼。            | [製品](../remote/artifacts/)             |
| **Release**          | 不可變的製品、設定（密鑰以參照出現）與部署宣告。      | [應用程式發布](../application-releases/) |
| **Change**           | 一次有身分的執行狀態變化。                            | [變更](../transitions/)                  |
| **Outcome**          | 一次 Change 的結局及其證據。                          | [結局](../transitions/#結局)             |
| **Probe**            | 外掛註冊的具名健康檢查。                              | [探針](../probes/)                       |
| **Trust policy**     | 維運制定的信任等級、授予、核准與撤銷規則。            | [信任](../trust/)                        |

## 其他術語

| 術語          | 說明                                               | 延伸閱讀                     |
| ------------- | -------------------------------------------------- | ---------------------------- |
| **Fork**      | 執行中外掛的控制代碼，擁有自己的設定和 `Scope`。   | [生命週期](../lifecycle/)    |
| **Event**     | 具型別的標記。處理函式屬於註冊它的外掛。           | [事件](../events/)           |
| **Intercept** | 對某個 fork 及其所有子孫修改 `Context.Reference`。 | [Intercept](../intercepts/)  |
| **Entry**     | `graft.yml` 中的一行，部署一個實例。               | [設定檔](../config-file/)    |
| **Loader**    | 把項目清單轉成 Change，並在設定被編輯時保持同步。  | [Loader API](../loader-api/) |

## 各部分的關係

1. 外掛被**載入**成 fork。同一個外掛載入兩次，會得到兩個獨立的 fork。
2. fork 可以**發布**服務，也可以**注入**其他 fork 發布的服務。
3. fork 可以**載入子外掛**。父外掛停止時，子外掛也會停止。
4. 領域和 intercept 決定 fork 及其子外掛能看到什麼。
5. fork 的程式碼通常在應用程式行程裡執行。透過
   [Remote](../remote/overview/)，它也可以在子行程、worker 或另一台機器上執行，而它的服務仍然照常在應用程式中發布和注入。

## 保證

| 保證                       | 來源                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 相依項目經過宣告並受檢查   | `inject` 由編譯器檢查。                                    |
| 消費者先於提供者停止       | [服務撤回流程](../services/#服務撤回流程)。                |
| 資源一定會釋放             | 每個 fork 擁有一個 `Scope`；任務屬於 `FiberSet`。          |
| 失敗保留完整的 `Cause`     | [fork 狀態](../lifecycle/#fork-狀態)、[錯誤](../errors/)。 |
| 失敗的變更讓舊外掛繼續執行 | [變更結局](../transitions/#結局)。                         |

## 建立在 Effect 之上

Graft 不另造一套詞彙，而是直接對應到 Effect：

| 在 Graft 中           | 在 Effect 中                 |
| --------------------- | ---------------------------- |
| 外掛啟動              | 在 `Scope` 中執行的 `Effect` |
| 服務                  | `Context` 鍵                 |
| 外掛設定              | `Schema`                     |
| 背景任務              | 由 `FiberSet` 持有的 `Fiber` |
| 重試                  | `Schedule`                   |
| 基於 Reference 的設定 | `Context.Reference`          |

Graft 只補上 Effect 沒有的部分：可在執行期間出現和消失的服務、外掛樹、事件、設定檔和變更。讓外掛程式碼遵循這些對應關係的習慣，請見[外掛中的 Effect](../best-practices/effect/)。
