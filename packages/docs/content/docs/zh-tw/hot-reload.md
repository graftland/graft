使用 `graft start --watch`
時，已觀察的外掛模組或相依模組變更後，會用新程式碼取代受影響的外掛。行程繼續執行，不是從外掛模組載入的部分也繼續執行，例如環境中的服務。

## 儲存後會發生什麼

1. Graft 先合併原生事件路徑，再檢查已觀察的檔案。事件本身不會觸發重載；只有檔案內容或追蹤的本機解析結果實際變更才會觸發。儲存相同內容或修改無關檔案不會重載外掛。
2. 自動重載只讓變更的模組實例，以及直接或間接匯入它們的模組失效，包括循環相依。只有受影響的入口會重新匯入；原先匯出同一個 Plugin 物件的入口會一起檢查。未變更的相依模組和獨立入口保留原有實例。
3. 所有候選通過匯入、匯出身分及解析檢查後，才透過一次
   [`Graft.replace`](../lifecycle/#取代外掛)
   交易發布取代。受影響的 fork 依正常的[服務撤回順序](../services/#服務撤回流程)重新啟動，共用的相依模組在整批取代中保持一致。
4. 候選失敗時，舊外掛繼續執行，並記錄完整 cause。HMR 保留待處理的變更和失敗觀察，等待下一次變更。檔案已刪除的外掛入口是例外：它會退出這次重載，既有 fork 繼續執行到卸載。重載期間收到的事件會留給下一輪處理。

重載嘗試傳回 `Reloaded` 或 `Skipped` 後，CLI 會呼叫
`loader.retry`，重試失敗的項目並重新讀取整棵樹的 `!env`
值。因此，修正外掛後不必重新啟動行程，就能再次載入。

公開的 `hmr.reload` 一律強制重新匯入所有已註冊入口及其受追蹤的相依模組，與
`watch`
的增量重載不同。即使沒有入口，它也會推進匯入視圖，讓首次失敗的匯入可以重試。

每個模組實例保留自己的解析視圖。舊程式碼稍後執行的動態匯入，包括啟用清理期間的匯入，不會切換到全域最新版本。重用的模組保留相依關係；尚未執行過的動態匯入無法事先發現。

相鄰的檔案事件會經過 50 毫秒防抖動。CLI 篩選設定目錄及其子目錄中的
`.js`、`.mjs`、`.cjs`、`.ts`、`.mts` 和 `.cts` 檔案，排除
`node_modules`。YAML 編輯由載入器處理。

HMR 每秒輪詢檔案中繼資料和本機解析結果。stat 快速路徑會略過中繼資料未變的檔案讀取；收到原生事件時，即使 stat 未變，也會強制檢查內容。閒置時至少每十秒檢查一次內容，因此即使儲存後的大小和時間戳記都相同、通知也遺失了，仍能偵測變更。匯入基準保存實際載入位元組的 SHA-256 摘要，因此也能發現匯入後、監看器安裝前的儲存。透過設定新增外掛本身不會觸發重載。

即使設定
`recursive: true`，HMR 也是依觀察到的相依圖，為相關目錄安裝非遞迴監看，不會走訪無關目錄或
`node_modules`。實際載入的 `dist`
模組仍受觀察；缺少的路徑由最近的現存上層目錄監看，目錄集合每秒更新。檢查遵循監看路徑、`recursive`
和
`filter`，並在串流關閉時停止。檔案讀取在工作階段鎖之外以有限並行執行，只有觀察版本仍相符時才接受結果。

每次觀察都屬於某次匯入嘗試及其實際讀取的位元組。新嘗試完成後，輪詢會改用這些位元組作為基準，包括檔案在重載期間回到先前快照的情況。失敗的嘗試若已讀取來源位元組，也會更新基準；沒有新變更時，不會陷入輪詢重試迴圈。

不完整的寫入可能導致重載失敗。Graft 會記錄完整的 cause 並繼續監看。之後的內容變更即使沒有原生事件，也能讓它恢復。CLI 也會記錄 watcher 的 I/O 失敗，並在一秒後重新安裝 watcher。

CLI 會在設定項目存活期間，替每個模組登記。移除或停用項目時，會釋放它的租約（lease）。最後一個租約關閉後，重載就不再匯入該項目。等待中和啟用失敗的項目會保留租約，讓之後的變更仍能讓它們恢復。已卸載的項目及其獨占的 CommonJS 相依套件，不會阻擋其餘的項目。輪詢也會跟隨租約。它涵蓋每個存活項目執行中的相依圖，以及最近一次尚未提交的匯入嘗試，包括失敗的匯入，以及重試所需、但尚不存在的本地檔案。最後一個擁有者釋放後，這些路徑就會退出輪詢。成功取代後，只回收使用中的入口和待重試入口都不再需要的觀察資訊；重用的相依模組實例仍保留歸屬。仍有擁有者的路徑發生真正的 I/O 錯誤時，監看串流仍會失敗。

假設兩個項目原本匯出同一個 Plugin 物件，現在卻匯出不同的物件。這時重載會傳回
`Skipped`，`reason` 為
`ambiguous-exports`，並列出發生衝突的模組 URL。CLI 會回報需要重新啟動，所有舊外掛維持原狀。恢復共用的匯出，重載也能恢復。新舊取代身分還必須與執行階段的 alias 相容。例如
`P → Q, Q → R` 無法表示兩次獨立的取代。此時重載會傳回 `Skipped`，`reason` 為
`identity-conflict`，並列出發生衝突的模組 URL。驗證會在發布 alias 或變更任何 fork 之前，拒絕整批取代。

在取消期間才完成的失敗，會在恢復可中斷狀態之前，以完整的 Exit 交接。HMR 會記錄本來可能被取消掩蓋的原始失敗，包括完整的 Cause。

如果帶版本的模組匯入 `node:module` 或 `module`，HMR 會保守地要求重新啟動。這會在
`createRequire` 呼叫命中快取之前，先記錄原生載入能力。它涵蓋 `require(esm)`
以及 CommonJS。即使只使用該模組中不相關的工具函式，這張相依圖也會退出熱重載。需要重載的相依套件，請使用 ESM 匯入。

即使沒有檔案通知，監看器也會回報已知的原生載入重新啟動要求，包括外掛在啟動後才取得該能力的情況。定期檢查不會重複回報相同狀態；這項警告不代表已執行重載。

本機檔案入口及其可達的相依關係，會依模組實例保留匯入方、請求路徑和實體目標。如果入口或輔助模組的符號連結改指向新的目標，重載會在取代任何外掛之前傳回
`Skipped / restart-required`，並列出受影響的請求 URL。匯入前、發布取代前及輪詢都會檢查同一份由租約持有的相依圖；失敗待重試的圖會保留到租約釋放。即使新舊內容相同、原生通知遺失，輪詢仍能偵測目標變更。請重新啟動以使用新目標；HMR 不會清除 Node 的解析快取。這項檢查不會重新解析裸套件名稱或套件的 export
map。

## 外掛模組的規則

- **匯入模組不得產生副作用。** Graft 重載時會重新匯入受影響的模組，而只有
  `apply` 是在 Graft 能關閉的 scope 內執行。請在 `apply`
  中開啟連線、啟動伺服器和設定計時器。
- 只有 ECMAScript 模組可以重載。CommonJS 和原生相依模組需要重新啟動行程。Graft 依模組實例追蹤相依關係，包括
  `apply` 中的動態匯入。只要仍有入口租約可連到這類相依模組，重載就傳回
  `Skipped / restart-required`。
- `node_modules`
  中的套件是共用的，不會重載。Effect 和 Graft 本身必須始終只有一份。有一個例外：外掛所在的那個模組。來自某個套件的外掛會被重新匯入，但該套件的其他檔案不會。
- 支援的最低 Node.js 版本是 22.19。這與 CLI 的 Effect
  Node 轉接器的要求一致，也提供了 `module.registerHooks`。

## 限制

Node 的 ESM 快取不會淘汰帶版本的模組實例。增量重載減少了新建實例的數量，但長時間開發工作階段仍會累積模組實例。HMR 依使用中的租約、待重試租約及目前的匯入視圖，回收原始碼摘要、相依觀察和可達性快取；為了讓舊程式碼仍能匯入模組，精簡的路由視圖會保留到工作階段關閉。這既不保證行程記憶體有固定上限，也沒有消除 Node 快取中的累積。需要時請重新啟動行程；HMR 不負責監督或重新啟動子行程。正式環境不要使用
`--watch`。

如果匯入永遠無法完成，會拖住之後的重載和關閉流程。例如模組頂層的 `await`
一直不會 resolve。這是因為動態匯入無法取消。

## 在自己的程式中使用

`@graftland/hmr` 套件可以不依賴 CLI 獨立使用：

```ts
import * as Hmr from "@graftland/hmr"
import { ModuleResolver } from "@graftland/loader"

const program = Effect.gen(function* () {
	const hmr = yield* Hmr.make({ base: import.meta.url })
	const resolver = yield* ModuleResolver.make({
		base: directory,
		importer: hmr.importerScoped,
	})
	yield* Graft.provide(ModuleResolver.ModuleResolver, resolver)
	// ...load plugins through the resolver, then, after files changed:
	const result = yield* hmr.reload
	yield* Effect.log(result)
})
```

`make` 需要 `Graft.Graft` 和一個
`Scope`。關閉 scope 時，它會等待執行中的匯入完成，並移除模組掛鉤。匯入這個套件本身不會啟動任何東西。

| 成員                      | 作用                                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `make({ base, include })` | `base` 是解析名稱所依據的模組 URL，通常是 `import.meta.url`。`include(url)` 決定哪些檔案會取得新版本：預設是 `node_modules` 之外的所有檔案。                                                   |
| `importer(specifier)`     | 匯入外掛模組，登記會持續到 HMR 工作階段關閉。                                                                                                                                                  |
| `reload`                  | 強制完整重載所有已註冊入口及其受追蹤的相依模組。傳回包含已重載模組的 `Reloaded`，或在需要重新啟動時傳回 `Skipped`。模組無法匯入，或沒有匯出外掛時，以 `HmrError` 失敗，其 `cause` 是原始錯誤。 |
| `watch(paths, options)`   | 一個串流：`paths` 下已觀察檔案的內容或本機解析變更後，增量重載受影響的入口。先等待 `debounce`（預設 50 毫秒）以收集更多變更，然後重載。失敗的重載會以帶有 cause 的 `Failed` 發出，監看會繼續。 |

`importerScoped(specifier)` 傳回一個需要 `Scope`
的 Effect；每次呼叫都會持有一個項目租約，直到該 scope 關閉。請把它傳給
`ModuleResolver.make`，它同時接受 Effect importer 和 Promise
importer。以 Promise 為基礎的 `importer(specifier)`
則會在整個 HMR 工作階段內保留它的登記。

首次匯入失敗後，觀察租約仍由設定項目持有，與立即關閉的候選資源 scope 分離。修正模組後，即使原生通知遺失，也能透過輪詢復原。重試會取代觀察代次，移除或停用設定項目則關閉觀察 scope。

`importerScoped(specifier, { observationScope })`
將觀察租約與候選匯入的暫時資源分開。`ModuleResolver`
透過 importer 的第二個參數傳遞這個 scope。失敗項目等待重試時應保留它，取代觀察嘗試或移除項目時關閉它；候選資源仍在失敗時立即清理。省略此選項時使用呼叫端的 scope。

在同一匯入視圖中重新取得入口租約，會保留其快取身分。目前的視圖保存快取命中所需的資訊，但不監看沒有租約的入口。成功提交重載後，這份快取會被回收；只有使用中、待重試或重用的相依圖仍需要的觀察資訊會繼續保留。

原生 watcher 在來源資源清理完成後、進入背景合併邊界之前觀察完整 Exit。包含失敗的中斷會在這裡記錄完整 Cause，純中斷不記錄錯誤；一般後端失敗繼續交給消費端處理，不重複記錄。

`WatchOptions.filter(absolutePath)`
決定哪些檔案可以觸發重載。原生事件和定期的內容檢查使用同一個述詞；省略時會接受所有路徑。`recursive`
控制是否包含子目錄。例如：

```ts
hmr.watch([directory], {
	recursive: true,
	filter: (path) => path.endsWith(".mjs"),
})
```

重載失敗是包含完整 `Cause` 的 `Failed`
值。watcher 和內容檢查的 I/O 失敗會讓串流本身失敗，所以呼叫端也必須處理這個通道。`onReady`
表示 watcher 已安裝，並不保證作業系統會送達每一個事件。
