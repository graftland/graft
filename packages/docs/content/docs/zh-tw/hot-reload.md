---
title: 熱重載
description: 在嵌入式應用程式中協作式替換模組。
---

熱重載屬於直接嵌入的開發工具。`graft start` 不支援
`--watch`；修改後重新建置並重新啟動。嵌入式 HMR 不提供核心隔離或依靠終止完成的資源回收。

透過 [HMR API](../hmr-api/) 註冊模組租約並驅動重載。

## 儲存時會發生什麼

監看器偵測到觀察位元組改變後，HMR 匯入候選模組並驗證匯出。一次
[`Graft.replace`](../replace/) 操作替換受影響的外掛。獨立外掛繼續執行。

### 候選項目失敗時

匯入或驗證失敗時保留舊外掛。啟動失敗可能得到 `RolledBack` 或
`RecoveryFailed`，應保留完整 cause。存在 managed fork 時回傳
`Skipped / managed-fork`。

### 強制重載

呼叫 `hmr.reload`，強制重新匯入已註冊項目及其追蹤的相依項目。

## 什麼會觸發重載

向 `hmr.watch`
傳遞監看路徑和篩選條件。YAML 和環境更新由嵌入式應用程式明確呼叫 Loader
API 完成。

## 重載不適用的情況

CommonJS、原生載入能力或本地符號連結目標改變時需要重新啟動。匯出歧義和替換識別衝突回傳
`Skipped`，解決衝突後再重試。

## 外掛模組的規則

模組匯入不執行 I/O。透過外掛作用域內的 Effect 取得資源。共享 Effect 和 Graft；需要重載的程式碼使用 ECMAScript 模組。

## 限制

掛起的匯入可能阻塞嵌入式重載和關閉。Node 保留帶版本的 ESM 實例，因此記憶體沒有硬性上限。HMR 不監管行程。

## 變更偵測

原生事件請求內容檢查。輪詢每秒檢查中繼資料和本地解析；閒置內容稽核至少每十秒執行一次。相同位元組不觸發替換。監看失敗保留完整 cause。

## 租約與觀察

有作用域的 importer 擁有租約。最後一個租約關閉後，該項目不再參與重載和輪詢。失敗匯入的觀察保留到租約關閉或重試替換它們。請參閱[有作用域的 importer](../hmr-api/)。
