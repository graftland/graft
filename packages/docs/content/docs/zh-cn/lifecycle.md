---
title: 生命周期
description: 挂载的状态、它的归属，以及拆除它的顺序。
---

挂载不是一次性的构建。随着图变化，它被构建、拆除、再构建，每次都遵循固定的顺序。

## 挂载状态

| 状态        | 含义                                            |
| ----------- | ----------------------------------------------- |
| `Loading`   | 正在构建 Layer，或正在发布一个值。              |
| `Pending`   | 等待必需的服务。`missing` 列出缺少的键。        |
| `Active`    | 已构建并在服务；它的服务已经发布。              |
| `Failed`    | 构建、后台 fiber 或清理失败。`cause` 包含一切。 |
| `Unmounted` | 已移除。这是最后一个状态。                      |

挂载会自行在状态之间移动：

| 从        | 到          | 何时                              |
| --------- | ----------- | --------------------------------- |
| `Pending` | `Loading`   | 必需的服务出现。                  |
| `Active`  | `Loading`   | 某个依赖或它使用的发布发生变化。  |
| `Failed`  | `Loading`   | 规格或依赖变化，或 `retry` 到点。 |
| 任意      | `Unmounted` | scope 关闭，或运行 `unmount`。    |

## 归属

挂载属于创建它的 scope。

- 关闭该 scope 会卸载它。
- 在 Layer 里创建的挂载是这个挂载的子挂载，父级停止或重启时随之停止。
- `Graft.fork` 的后台 fiber 归挂载所有；`Effect.forkScoped`
  的 fiber 归拥有该 scope 的一方所有。

`Graft.layer` 本身随运行时关闭。关闭它会卸载图中的一切。

## 拆除顺序

当挂载因变化、失败、`restart` 或 `unmount` 被拆除时：

1. **停止构建**，如果它还在运行。
2. **撤回服务**，在一个事务里完成，并关闭这个挂载，使它不能再发布，新的消费者也无法再租借这些服务。
3. **排空消费者。** 等每个消费者释放租约，然后让它们各自按依赖重启。
4. **停止后台 fiber** 并关闭它们的 scope，等待清理完成。
5. **关闭挂载的 scope**，这会停止子挂载并运行 finalizer。
6. **释放挂载自己的租约**，即它需要的那些服务。

| 消费者的情况       | 重启之后           |
| ------------------ | ------------------ |
| 存在环境回落       | 使用回落值。       |
| 必需依赖，没有回落 | 变成 `Pending`。   |
| 可选依赖，没有回落 | 不含该服务地重建。 |

第 3 步期间，健康的后台 fiber 及其资源对消费者的 finalizer 仍然可用。如果排空超过 10 秒，Graft 会记录一条警告：两个挂载可能在互相等待。

拆除期间的失败并入挂载的 `Failed` `Cause`。`unmount` 把它报告为
`Mount.CleanupError`，它的 `cause` 保留原始原因。

## 重启与卸载

| 调用      | 作用                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------- |
| `await`   | 等到稳定（不再是 `Loading`）；`Pending` 算作稳定；`Failed` 以它的 `Cause` 失败，即使设置了 `retry`。 |
| `restart` | 即使什么都没变，也拆除并重新构建。等重建开始后才完成。                                               |
| `unmount` | 拆除挂载并从图中移除它，以及它下面的一切。                                                           |
| `stable`  | 等挂载及其子挂载都不再处于 `Loading`。                                                               |

并发和重复的 `unmount` 调用共享同一个清理结果。

### 挂载仍在构建时卸载

在挂载仍处于 `Loading`
时卸载，会取消构建并正常成功。只有当构建中已获取资源的 finalizer 自身中断或失败时，`unmount`
才以 `Mount.CleanupError` 失败；这种失败不会被报告为
`Release.ReleaseInterrupted`。

| 构建期间的 finalizer | `unmount` 的 cause                 | 日志                                                     |
| -------------------- | ---------------------------------- | -------------------------------------------------------- |
| 只有自中断           | 仅含中断原因                       | 无。                                                     |
| 以 defect 或失败结束 | 该 defect 或失败，另含一个中断原因 | 记录一条错误：`Releasing the mount's resources failed`。 |

已经完成加载的挂载保持上面的行为不变。

## 重建就是一次新的激活

每次构建都是独立的：

- 它的 finalizer 在自己的 scope 里运行。
- 它的后台 fiber 是新的；没有 fiber 能跨过一次重建。
- 它的服务是新的值，即使还是同一个 Layer。

任何必须跨重建存活的东西，应该放在构建 `Graft.layer`
的环境里，或者放在一个不会被重建的父挂载里。

## 来自环境的服务

构建 `Graft.layer` 的环境里的服务无需发布即可满足
`requires`。它们的存在时间与那个环境一致，而不是与某个挂载一致。把连接、文件系统和设置这类贯穿整个程序的资源放进环境。
