---
title: 热重载
description: 在嵌入式应用中协作式替换模块。
---

热重载属于直接嵌入的开发工具。`graft start` 不支持
`--watch`；修改后重新构建并重启。嵌入式 HMR 不提供内核隔离或依靠终止完成的资源回收。

通过 [HMR API](../hmr-api/) 注册模块租约并驱动重载。

## 保存后会发生什么

watcher 检测到观察字节改变后，HMR 导入候选模块并验证导出。一次
[`Graft.replace`](../replace/) 操作替换受影响的插件。独立插件继续运行。

### 候选失败时

导入或验证失败时保留旧插件。激活失败可能得到 `RolledBack` 或
`RecoveryFailed`，应保留完整 cause。存在 managed fork 时返回
`Skipped / managed-fork`。

### 强制重载

调用 `hmr.reload`，强制重新导入已注册条目及其跟踪的依赖。

## 什么会触发重载

向 `hmr.watch`
传递监听路径和过滤条件。YAML 和环境刷新由嵌入式应用显式调用 Loader API 完成。

## 重载未生效的情形

CommonJS、原生加载能力或本地符号链接目标改变时需要重启。导出歧义和替换身份冲突返回
`Skipped`，解决冲突后再重试。

## 插件模块的规则

模块导入不执行 I/O。通过插件作用域内的 Effect 获取资源。共享 Effect 和 Graft；需要重载的代码使用 ECMAScript 模块。

## 限制

挂起的导入可能阻塞嵌入式重载和关闭。Node 保留带版本的 ESM 实例，因此内存没有硬性上限。HMR 不监管进程。

## 变更检测

原生事件请求内容检查。轮询每秒检查元数据和本地解析；空闲内容审计至少每十秒执行一次。相同字节不触发替换。监听失败保留完整 cause。

## 租约与观察

有作用域的 importer 拥有租约。最后一个租约关闭后，该条目不再参与重载和轮询。失败导入的观察保留到租约关闭或重试替换它们。参见[有作用域的 importer](../hmr-api/)。
