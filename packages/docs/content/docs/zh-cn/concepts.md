Graft 把一个应用作为一棵**插件树**来运行。本页列出各个组成部分，每一行都链接到详细说明它的页面。

## 核心词

这些词在所有包和页面中只有一个含义。

| 词                   | 含义                                                  | 了解更多                             |
| -------------------- | ----------------------------------------------------- | ------------------------------------ |
| **Plugin**           | 声明并实现一项能力的值：配置、依赖、服务与启动逻辑。  | [插件](../plugins/)                  |
| **Instance**         | 部署中有稳定身份的插件。Loader 条目的 id 就是实例名。 | [配置文件](../config-file/)          |
| **Service**          | Effect 的服务。Graft 补充运行期间的发布、撤回与租约。 | [服务](../services/)                 |
| **Contract**         | Effect 的 `RpcGroup` 加上每个操作的身份。             | [远程契约](../remote/contracts/)     |
| **Realm**            | 服务与贡献的可见边界。                                | [领域](../isolation/)                |
| **Deployment group** | 共享一个单元、单元结束时一同受影响的一组实例。        | [单元](../units/)                    |
| **Unit**             | 承载实例的 Worker、子进程或 runner 上的执行。         | [单元](../units/)                    |
| **Generation**       | 一个实例的一次执行，从启动到结束。                    | [变更](../transitions/)              |
| **Placement**        | 单元的种类及其管理者。                                | [单元](../units/)                    |
| **Artifact**         | 内容寻址、运行期间字节不变的插件代码。                | [制品](../remote/artifacts/)         |
| **Release**          | 不可变的制品、配置（密钥以引用出现）与部署声明。      | [应用发布](../application-releases/) |
| **Change**           | 一次有身份的运行态变化。                              | [变更](../transitions/)              |
| **Outcome**          | 一次 Change 的结局及其证据。                          | [结局](../transitions/#结局)         |
| **Probe**            | 插件注册的具名健康检查。                              | [探针](../probes/)                   |
| **Trust policy**     | 运维制定的信任等级、授予、批准与撤销规则。            | [信任](../trust/)                    |

## 其他术语

| 术语          | 含义                                                        | 了解更多                     |
| ------------- | ----------------------------------------------------------- | ---------------------------- |
| **Fork**      | 运行中插件的句柄，拥有自己的配置和 `Scope`。                | [生命周期](../lifecycle/)    |
| **事件**      | 带类型的令牌。处理函数归注册它的插件所有。                  | [事件](../events/)           |
| **Intercept** | 对某个 fork 及其下所有 fork 的 `Context.Reference` 的修改。 | [Intercept](../intercepts/)  |
| **条目**      | `graft.yml` 的一行，部署一个实例。                          | [配置文件](../config-file/)  |
| **加载器**    | 把条目列表变成 Change，并在条目被编辑时保持同步。           | [Loader API](../loader-api/) |

## 各部分如何关联

1. 插件被**加载**为一个 fork。同一个插件加载两次，会得到两个相互独立的 fork。
2. fork 可以**发布**服务，也可以**注入**其他 fork 发布的服务。
3. fork 可以**加载子插件**。父级停止时，子级也会停止。
4. 领域和 intercept 决定 fork 及其子级能看到什么。
5. fork 的代码通常在应用进程里运行。借助
   [Remote](../remote/overview/)，它也可以在子进程、worker 或另一台机器上运行，而它的服务仍然照常在应用中发布和注入。

## 保证

| 保证                       | 来源                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 依赖经过声明并受到检查     | `inject` 由编译器检查。                                    |
| 消费者先于提供者停止       | [服务撤回流程](../services/#服务撤回流程)。                |
| 资源总会被释放             | 每个 fork 拥有一个 `Scope`；任务归 `FiberSet` 所有。       |
| 失败保留完整的 `Cause`     | [fork 状态](../lifecycle/#fork-状态)、[错误](../errors/)。 |
| 失败的变更让旧插件继续运行 | [变更结局](../transitions/#结局)。                         |

## 构建于 Effect 之上

Graft 不引入平行的概念体系，而是直接映射到 Effect：

| 在 Graft 中           | 在 Effect 中                 |
| --------------------- | ---------------------------- |
| 插件 activation       | 在 `Scope` 中运行的 `Effect` |
| 服务                  | `Context` 键                 |
| 插件配置              | `Schema`                     |
| 后台任务              | 由 `FiberSet` 持有的 `Fiber` |
| 重试                  | `Schedule`                   |
| 基于 Reference 的设置 | `Context.Reference`          |

Graft 只补充 Effect 所没有的部分：可在运行期间出现和消失的服务、插件树、事件、配置文件和变更。让插件代码遵循这些对应关系的习惯，见[插件中的 Effect](../best-practices/effect/)。
