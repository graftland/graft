## Three promises

<CardGrid>
	<Card title="Rootstock">
		Services are Effect <code>Context</code> keys, provided by layers or by
		other plugins. A plugin lists what it needs in <code>inject</code>, and the
		compiler checks the list. See <a href="services/">services</a>.
	</Card>
	<Card title="Pruning">
		Each plugin runs in its own <code>Scope</code>. When it goes away, its
		dependents stop first, then its finalizers run. A failure keeps its full{" "}
		<code>Cause</code>. See <a href="lifecycle/">lifecycle</a>.
	</Card>
	<Card title="Top-working">
		Change the variety without felling the tree. Hot reload swaps only the
		plugins your change affects, in one transaction, and keeps the old code if
		the new code fails. See <a href="hot-reload/">hot reload</a>.
	</Card>
</CardGrid>

## A first graft

```ts
import { Graft, Plugin } from "@graftland/graft"
import { Context, Effect, Schema } from "effect"

class Greeter extends Context.Service<
	Greeter,
	{ readonly greet: (name: string) => Effect.Effect<void> }
>()("app/Greeter") {}

// Publishes a Greeter while it is loaded.
const greeter = Plugin.make({
	name: "greeter",
	config: Schema.Struct({ greeting: Schema.String }),
	apply: ({ greeting }) =>
		Graft.provide(Greeter, {
			greet: (name) => Effect.log(`${greeting}, ${name}!`),
		}),
})

// Starts once a Greeter exists, and stops before it goes away.
const hello = Plugin.make({
	name: "hello",
	inject: [Greeter],
	apply: () => Effect.flatMap(Greeter, (greeter) => greeter.greet("world")),
})
```

## Packages

| Package                      | What it does                                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `@graftland/graft`           | A plugin framework built on Effect: plugins, forks, services, isolation, events and logs.                               |
| `@graftland/loader`          | Loads plugins from a list of entries or a YAML config file.                                                             |
| `@graftland/hmr`             | Reloads plugin modules on Node.js without restarting the process.                                                       |
| `@graftland/cli`             | The `graft` command: `start`, `create`, `add` and `remove`.                                                             |
| `@graftland/create`          | Makes a new Graft project. `graft create` uses it.                                                                      |
| `@graftland/package-manager` | Installs dependencies with npm, pnpm or Yarn. A failed install is undone by [snapshot rollback](cli/#package-managers). |
| `@graftland/plugin-remote`   | Runs a plugin in a child process, a worker or on another machine. See [Remote](remote/overview/).                       |

All packages share one version number and are released together. They need
`effect` 4.1.x.

The garden is only on this page. In the rest of the documentation and in the
code, a `Scope` is still a `Scope`. Graft draws its plugin model from
[cordis](https://github.com/cordiverse/cordis). Where cordis composes across
space and time, Graft keeps to the garden.
