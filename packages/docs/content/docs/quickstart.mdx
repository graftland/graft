import { Steps } from "@astrojs/starlight/components"

You need Node.js 22.19 or later. This is the version that the CLI's Effect Node
adapter needs.

<Steps>

1. Create a project. Press <kbd>Enter</kbd> to accept each default; the command
   installs the dependencies:

   ```sh
   npm create @graftland@latest my-app
   cd my-app
   ```

   The files to start with:

   | File             | What it is                                             |
   | ---------------- | ------------------------------------------------------ |
   | `graft.yml`      | The config file: which plugins to load, and how.       |
   | `src/hello.ts`   | A plugin that logs a message from its config.          |
   | `src/greeter.ts` | A plugin that publishes the `Greeter` service.         |
   | `src/ticker.ts`  | A plugin that injects `Greeter` and greets on a timer. |
   | `tsconfig.json`  | Type checking for `npm run typecheck`.                 |

   [`graft create`](../cli/#graft-create) lists the questions, the other
   templates and the options that skip the questions.

2. Start the application and watch for changes:

   ```sh
   npm run dev
   ```

   `hello` logs `Hello from Graft!`, and `ticker` logs `Hello, Graft!` every 3
   seconds through the `Greeter` that `greeter` publishes. The process keeps
   running until you press <kbd>Ctrl</kbd>+<kbd>C</kbd>. Then Graft unloads
   every plugin.

3. Change the config while the app runs. Open `graft.yml` and change the
   greeting:

   ```yaml
   - id: greeter
     name: ./src/greeter.ts
     config:
       greeting: Hi
   ```

   When you save, Graft stops `ticker` first, because it uses the `Greeter`,
   then restarts `greeter` with the new greeting and starts `ticker` again. You
   see `Ticker stopped`, `Greeter stopped`, then `Hi, Graft!`. `hello` is not
   touched.

4. Change the code while the app runs. In `src/ticker.ts`, change `"3 seconds"`
   to `"1 second"` and save. `tsc` rebuilds `dist`, and Graft deploys the new
   code as one Change. The three example plugins share one package, so all three
   restart; give a plugin its own package to reload it alone. If the new code
   fails to start, the running entries stay as they are and Graft logs the
   error.

5. Take a dependency away. Add `disabled: true` to the `greeter` entry and save.
   `ticker` still needs the `Greeter`, so Graft rejects the edit, logs why, and
   keeps everything running. Disable `ticker` too, or remove the line, and save
   again.

</Steps>

## The example plugins

```ts title="src/greeter.ts"
import { Context, Effect, Schema } from "effect"

import { Graft, Plugin } from "@graftland/graft"

/** Greets by name. Other plugins list it in `inject` to use it. */
export class Greeter extends Context.Service<
	Greeter,
	{ readonly greet: (name: string) => Effect.Effect<void> }
>()("app/Greeter") {}

// Publishes a Greeter while it is loaded. Plugins that use it stop first.
export default Plugin.make({
	name: "app/greeter",
	config: Schema.Struct({ greeting: Schema.String }),
	provides: [Greeter],
	apply: ({ greeting }) =>
		Effect.gen(function* () {
			yield* Effect.addFinalizer(() => Effect.logInfo("Greeter stopped"))
			yield* Graft.provide(Greeter, {
				greet: (name) => Effect.logInfo(`${greeting}, ${name}!`),
			})
		}),
})
```

```ts title="src/ticker.ts"
import { Effect, Schedule, Schema } from "effect"

import { Plugin } from "@graftland/graft"

import { Greeter } from "./greeter.ts"

// Starts once a Greeter exists and greets on a schedule. The task belongs to
// the plugin, so it stops when the plugin stops or reloads.
export default Plugin.make({
	name: "app/ticker",
	config: Schema.Struct({ name: Schema.String }),
	inject: [Greeter],
	apply: ({ name }) =>
		Effect.gen(function* () {
			const greeter = yield* Greeter
			yield* Plugin.fork(
				greeter.greet(name).pipe(Effect.repeat(Schedule.spaced("3 seconds"))),
			)
			yield* Effect.addFinalizer(() => Effect.logInfo("Ticker stopped"))
		}),
})
```

`inject: [Greeter]` is checked by the compiler: remove it, and
`npm run typecheck` reports that `apply` uses a service it did not declare. Node
runs the TypeScript files as they are, removing the types, so there is no build
step. A plugin module exports its plugin as the default export, or as an export
named `plugin`. Importing the module must not start anything. Open connections,
timers and servers inside `apply`, so that Graft can release them. See
[Plugins](../plugins/) and [Services](../services/).

## Add a plugin from npm

```sh
npx graft add graft-plugin-review
```

`graft add` installs packages with the project's package manager. If the install
fails, it puts `package.json` and the lockfile back as they were. While it
installs or recovers, do not edit project files or run another installer. A
rollback overwrites changes. It does not merge them. See
[installation ownership and recovery](../cli/#package-managers). Then add an
entry for the plugin to `graft.yml`. Its `name` can be the short name `review`:
Graft looks for `review` itself, then for `@graftland/plugin-review` and
`graft-plugin-review`, and fails if both of those are installed. See
[Config file](../config-file/).
