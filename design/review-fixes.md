# Final review: findings and dispositions

The one independent review of all phases (GPT-6 Astra, 2026-11-08, its own
worktree, ran build, typecheck and every test) reported 5 high and 4 medium
findings. Claude fixed them on `fixes/claude`; each fix has a regression test.

| Id  | Finding                                                                                                             | Fix                                                                                                                                                                                                                                                                                   | Evidence                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| H1  | Phase 2 deleted the Linux sandbox and its attack tests; untrusted code could only run unconfined                    | `Units.target({ placement: "Process", confinement: "Sandbox" })`: prlimit + bubblewrap (namespaces, no capabilities, cleared environment, read-only artifacts, Node permissions), bundled unit entry, fails closed; part of the target identity; `setPolicy({ sandbox })` requires it | `sandbox.test.ts`: hostile canary escapes unconfined, is `Accepted` only sandboxed; passed on Linux (NixOS VM, bubblewrap) |
| H2  | A Loader edit called `setPolicy({ allowed: [identity] })` and could undo a revocation                               | `setPolicy` takes `allowed` and `sandbox` optionally; the Loader sets reference values only                                                                                                                                                                                           | `supervision.test.ts`: values-only update keeps the revocation                                                             |
| H3  | At the Conclusion gate a later exit produced `Accepted` with `healthy: false`; shutdown waited forever for a record | The conclusion reports member facts of finished execution; a later exit goes to the supervisor (deferred until release); shutdown skips Changes whose concluding record can no longer be acknowledged                                                                                 | `recording-duties.test.ts`: two tests                                                                                      |
| H4  | Record ids collided across kernel runs (`change-1/Intent`)                                                          | Each kernel start has a run id; payloads, journal ids and history carry it                                                                                                                                                                                                            | `journal.test.ts`: change-1 of two runs stays apart                                                                        |
| H5  | A partial write followed by a retry left a corrupt journal yet acknowledged                                         | Every append first truncates the segment to the last acknowledged boundary                                                                                                                                                                                                            | `journal.test.ts`: torn write then retry reads back cleanly                                                                |
| M1  | A supervisor restart rejected `Busy` at admission was counted and forgotten                                         | Busy or capacity rejections defer the restart and refund the attempt; other rejections escalate                                                                                                                                                                                       | `supervision.test.ts`: busy admission defers without counting                                                              |
| M2  | Recording admission scanned every Change and record                                                                 | Two counters (unacknowledged records, promised stage slots) kept incrementally                                                                                                                                                                                                        | `recording-duties.test.ts`: counters equal a full recount in every observed state                                          |
| M3  | Member facts and records lacked per-member execution evidence                                                       | `MemberFact.startingHealthy` and `attempt`; records carry per-member facts, phase and rendered cause                                                                                                                                                                                  | `recording-duties.test.ts`, `decision-core.test.ts`, `journal.test.ts`                                                     |
| M4  | README and docs said a failed Change leaves entries running, and every upgrade ends in five outcomes                | Qualified in README (three languages), `cli.md`, `quickstart.mdx`, `concepts.md` and skills                                                                                                                                                                                           | Documentation                                                                                                              |

Found while fixing: a sandboxed plugin bundles its own Effect, and its schema
refinements (for example `Schema.Int`) reject valid values in the unit's
decoder. Documented in `trust.md`; plain config shapes work.
